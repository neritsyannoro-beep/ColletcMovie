# CollectMovie

Личный трекер просмотренного: **фильмы, сериалы, аниме**. Ищешь по названию, добавляешь
в коллекцию, ставишь оценку от 1 до 10. Всё хранится **локально на телефоне** — никаких
аккаунтов, серверов и подписок.

Открывается как обычный сайт, но ставится на главный экран и работает как приложение,
в том числе без интернета (кроме самого поиска).

## Как открыть на телефоне

Один раз включить публикацию (у автоматики нет прав сделать это за тебя):

1. Репозиторий → **Settings** → **Pages**.
2. *Build and deployment* → **Source: GitHub Actions**.
3. Вкладка **Actions** → workflow *Deploy to GitHub Pages* → **Re-run jobs**
   (или просто сделать любой пуш — дальше деплой идёт сам при каждом изменении).
4. Через пару минут открыть на телефоне:
   **https://neritsyannoro-beep.github.io/ColletcMovie/**

### Добавить на главный экран (важно)

- **iPhone (Safari):** кнопка «Поделиться» → *На экран «Домой»*.
- **Android (Chrome):** меню «⋮» → *Добавить на главный экран*.

Это не просто ярлык: после установки браузер перестаёт считать сайт временным и
**не удаляет коллекцию** при чистке кэша. Сделать это стоит сразу.

## Что умеет

- **Поиск** по фильмам, сериалам и аниме — с постерами, годом и описанием.
- **Статусы**: просмотрено, смотрю, в планах, брошено.
- **Оценка 1–10** и заметка к каждому тайтлу.
- **Фильтры** по типу и статусу, сортировка (новые, оценка, А–Я, год), поиск по коллекции.
- **Советы** — что посмотреть дальше, отдельно по фильмам, сериалам и аниме,
  на основе того, что ты оценил выше всего в этой категории.
- **Статистика**: сколько всего, средняя оценка, распределение оценок, топ по оценке.
- **Ручное добавление** — если в базах чего-то нет.
- **Бэкап** в файл и восстановление из файла, с напоминанием, когда копия устарела.
- Работает офлайн, весь интерфейс — под телефон.

## Как работают советы

Вкладка «Советы» ничего не выдумывает — она опирается на твои оценки.

1. Из категории берутся до восьми просмотренных тайтлов с самыми высокими оценками.
2. Для каждого запрашивается «похожее»: у TMDB — для фильмов и сериалов,
   у MyAnimeList — для аниме (там подборки составляют сами зрители).
3. Ответы складываются. Чем выше твоя оценка исходного тайтла и чем чаще
   один и тот же фильм советуют разные твои любимые — тем он выше в списке.
4. Всё, что уже есть в коллекции, отсеивается.

Под каждой карточкой написано, почему её предлагают: «Похоже на «Морпехи» и
«Повелитель бури»». Добавляется такой тайтл сразу со статусом «В планах».

Категории считаются независимо: советы по аниме строятся только на аниме,
по сериалам — только на сериалах.

Подборка кэшируется на шесть часов и пересчитывается сама, когда меняются
оценки. Кнопка обновления в углу пересчитывает принудительно.

**Для фильмов и сериалов нужен ключ TMDB** — у iTunes и TVmaze нет ничего
похожего на «рекомендации». Аниме советуется и без ключа.

## Откуда берутся фильмы

По умолчанию — из бесплатных открытых баз, ключи не нужны, всё работает сразу:

| Что        | Источник                        | Ключ |
|------------|---------------------------------|------|
| Аниме      | Jikan (MyAnimeList), при сбое AniList | не нужен |
| Сериалы    | TVmaze                          | не нужен |
| Фильмы     | iTunes Search                   | не нужен |

**Важное ограничение:** все три ищут по оригинальным названиям. «Человек паук»
или «Счастливое число Слевина» по-русски там не находятся — это особенность
самих баз, а не приложения. Русский поиск нормально работает только с ключом
TMDB, поэтому его стоит поставить, если смотришь и ищешь по-русски.

Аниме-база Jikan периодически отвечает 5xx. Приложение повторяет запрос, а если
она всё-таки лежит — молча переключается на AniList, так что аниме продолжает
находиться.

### Ключ TMDB — очень желателен

С ключом всё ищется по русским названиям — и фильмы, и сериалы, и аниме
(японская анимация распознаётся по языку и жанру и попадает в свою категорию).
Постеры тоже лучше.

1. Зарегистрироваться на [themoviedb.org](https://www.themoviedb.org/).
2. Settings → API → скопировать **API Key (v3 auth)**.
3. В приложении: **Настройки** → вставить ключ → *Сохранить*.

Ключ хранится только на твоём телефоне и никуда не отправляется, кроме самого TMDB.
Аниме в любом случае ищется через Jikan — там база полнее.

## Как не потерять коллекцию

Коллекция живёт **только в браузере этого телефона**. Ни на GitHub, ни на
каком-либо сервере её нет — приложение вообще не умеет никуда отправлять данные.
Отсюда всё остальное.

### Что её убивает

| Ситуация | Что будет |
|----------|-----------|
| Купил новый телефон | Коллекция не переедет сама |
| Удалил иконку с главного экрана | На iPhone вместе с ней удаляются и данные приложения |
| Очистил историю и данные сайтов в Safari | Копия, которая жила во вкладке Safari, пропадёт |
| Переустановил браузер | То же самое |
| Не заходил больше 7 дней (только через вкладку Safari, без иконки) | Safari вправе очистить хранилище сайта — у установленных на экран приложений этого ограничения нет |

Из-за последнего пункта иконку на главном экране стоит держать всегда: это не
ярлык, а именно установленное приложение с защищённым хранилищем.

**Важная особенность iPhone:** приложение с главного экрана и сайт во вкладке
Safari хранят данные раздельно. То, что добавлено через иконку, во вкладке
Safari не появится, и наоборот. Пользуйся чем-то одним — иконкой.

### Что её спасает

Единственный надёжный способ — **резервная копия файлом**:

**Настройки → Сохранить резервную копию.** На айфоне откроется системная
шторка «Поделиться» — оттуда файл кладётся в «Файлы», iCloud Drive, или
отправляется себе в избранное в мессенджере. Файл маленький, обычный JSON.

Приложение само напомнит: если копии нет вообще или ей больше двух недель, над
списком появится жёлтая плашка с кнопкой. Дата последней копии видна в настройках.

**Восстановление и переезд на новый телефон:**

1. На старом — сохранить копию, закинуть файл в облако или мессенджер.
2. На новом — открыть приложение, **Настройки → Загрузить из файла**, выбрать этот файл.
3. Спросит, заменить коллекцию или добавить к существующей. «Отмена» = добавить,
   так что случайно ничего не затрёшь.

Пока файл бэкапа лежит в облаке, потерять коллекцию нельзя, что бы ни случилось
с телефоном.

### Что сделано на стороне приложения

Внутри устройства коллекция дублируется, чтобы пережить мелкие сбои:

- **localStorage** — основное хранилище;
- **IndexedDB** — зеркало, переживает очистку localStorage;
- **три последних снимка** — на случай, если основная запись побьётся.

При запуске берётся тот источник, где записей больше, остальные чинятся.
Приложение также просит у браузера пометить данные как защищённые от
автоочистки. Но всё это спасает только от сбоев на самом устройстве — от
потери или замены телефона защищает исключительно файл бэкапа.

## Локальный запуск

```bash
npx http-server -p 8080 -c-1
# открыть http://localhost:8080
```

Сборка не нужна — это статические файлы.

## Тесты

Сквозные тесты в реальном мобильном Chromium (Playwright), внешние API замоканы:

```bash
npx playwright install chromium   # один раз
npx http-server -p 8099 -c-1 &
node tests/e2e.mjs
node tests/recs.mjs
```

Проверяют поиск по всем трём источникам, добавление с оценкой, фильтры, сортировку,
статистику, экспорт, восстановление из IndexedDB после потери localStorage и ветку TMDB.

## Структура

```
index.html                 разметка всех четырёх экранов
assets/css/app.css         стили (тёмная тема, только мобильная вёрстка)
assets/js/app.js           экраны, фильтры, поиск, шторка, настройки
assets/js/store.js         хранилище: localStorage + IndexedDB + снимки, экспорт/импорт
assets/js/providers.js     источники поиска: TMDB, Jikan, AniList, TVmaze, iTunes
assets/js/recs.js          подбор советов на основе оценок
assets/js/ui.js            отрисовка карточек, шторки, статистики
sw.js                      service worker: офлайн-режим
manifest.webmanifest       описание PWA
tests/e2e.mjs              сквозные тесты
tests/recs.mjs             тесты вкладки «Советы»
```
